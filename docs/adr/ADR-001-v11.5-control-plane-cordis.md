# ADR-001 — v11.5 Control Plane and Cordis Boundary

Date: 2026-10-06
Status: Accepted for implementation branch

## Decision

Morn will not implement a generic plugin framework, generic agent harness,
generic sandbox or generic policy language.

The reference Composition Plane directly uses exact-pinned Cordis behind a
Morn-owned adapter. Cordis is replaceable and is not the canonical Work store.

DeepSeek Harness is an out-of-process Harness Provider through public SDK/ACP
interfaces. Pi is the second harness family used to test harness neutrality.

Morn-specific engineering concentrates on semantic contracts, durable Work
control, capability resolution/qualification, execution binding, governed
action attempts, receipt/reconciliation, outcome/acceptance and Domain
Profiles.

## Why

Cordis already provides Context, service slots, dependency injection and
lifecycle cleanup. Reimplementing those primitives adds maintenance cost
without differentiating Morn.

Cordis lifecycle effects are not sufficient for real business effects. A
purchase order, maintenance order, customer notification or physical action may
be irreversible, compensatable or outcome-unknown. Those facts require durable
Morn state and reconciliation.

## Consequences

- No domain/control-plane code imports Cordis directly.
- Active attempts are pinned to an ExecutionBinding; provider replacement cannot
  mutate an attempt in place.
- Agent/runtime completion never implies Outcome or Acceptance.
- Existing v1 contracts remain available while v11.5 resources are introduced
  alongside them; migration is explicit.
- Factory remains no-production-write until external evidence/authority gates
  are satisfied.
